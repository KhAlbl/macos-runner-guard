# Deterministic Artifacts and Adoption Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce byte-for-byte reproducible toolkit-source and per-instance ZIPs, verify them independently before safe extraction, and publish precise adoption/operations guidance without exposing live host state or claiming a release.

**Architecture:** Payload bytes are collected into typed regular-file members. `MANIFEST.json` covers the payload and excludes the two control files; `SHA256SUMS` covers payload plus manifest and excludes itself. A custom canonical ZIP32/STORE writer sets every header field. A separate parser verifies local and central records before descriptor-relative extraction into a new directory. Documentation and agent prompts consume only verified bundles.

**Tech Stack:** Python 3.9+ standard library (`hashlib`, `struct`, `zlib`, descriptor-relative `os` APIs); canonical JSON; ZIP32 specification; unittest/pytest; Markdown; final-byte secret scanning.

**Spec:** [Approved architecture §§10–15](../../ARCHITECTURE.md)

## Global Constraints

- Prerequisites: the first three child plans are accepted on the same exact branch head.
- Artifact manifest version is `macos-runner-guard.manifest.v1`; toolkit version is `0.1.0`.
- Build only from an explicitly reviewed clean source commit/tree or a fresh rendered-instance staging tree—never from an arbitrary clean `HEAD` and never from a live runner root.
- `MANIFEST.json` and `SHA256SUMS` exist only in fresh staging and archives; they are not committed at repository root.
- Archive limits are fixed at 256 total members including `MANIFEST.json` and `SHA256SUMS`, 8,388,608 bytes per member, 67,108,864 total uncompressed bytes, and 83,886,080 total archive bytes. Payload collection therefore permits at most 254 members.
- Fixed member time is `1980-01-01T00:00:00`; member names are portable ASCII. Every member-name sequence is strictly ascending by `path.encode("ascii")`: collected payload, manifest records, checksum records, ZIP local headers, ZIP central-directory records, verifier results, and extraction order. No component may rely on locale, filesystem enumeration order, or default Unicode collation.
- ZIP32, STORE, regular-file members only; no ZIP64, compression, encryption, data descriptors, extras, comments, or explicit directory entries.
- Do not publish a package, release, tag, asset, attestation, or hosted download in this plan.
- Do not call a digest a signature, authentication, origin proof, or trust root.
- All extraction tests use new disposable roots and prove no outside path changed after rejection.
- Run every development, unit-test, and builder command as `PYTHONPATH="$PWD/src" .venv/bin/python`; shell state is never assumed across tasks. Isolated installed-runtime `/usr/bin/python3 -I -S` commands never import the checkout.

`ArtifactPolicy.allowed_members` is a closed, bytewise-ordered path-to-mode contract, not a path-only allow-list. Paths must be unique, portable ASCII, and must not name `MANIFEST.json` or `SHA256SUMS`; each mode must be exactly one artifact-class-supported regular-file mode. `canonical_artifact_policy_sha256()` hashes the canonical complete policy, including class, ordered allowed members, and every limit. `collect_payload()` requires the observed path set and every observed mode to equal this contract—missing, extra, duplicate, or wrong-mode members fail closed—then returns a `VerifiedPayload` bound to that policy digest and the explicit already-verified source-binding SHA-256. For an instance that source binding is the exact non-circular rendered-payload binding digest; for toolkit source it is the canonical digest of the verified `SourceIdentity`. Every manifest, archive, and scanner consumer calls `validate_verified_payload()` with the explicit expected policy and source binding and rejects a forged record, policy substitution, source-binding substitution, missing/extra/reordered member, wrong mode, changed bytes, or digest mismatch. `ArtifactPolicy.maximum_members` counts payload plus both control files. `collect_payload()` rejects the 255th payload member; `build_canonical_zip()` rejects any total count above 256. The two builder-generated control files always use mode `0444` and are not `AllowedMember` entries.

`canonical_artifact_policy_bytes()` uses schema `macos-runner-guard.artifact-policy.v1`, the umbrella canonical JSON profile, explicit decimal limits, four-digit octal member modes, and exact ASCII order. `load_artifact_policy_bytes()` rejects noncanonical bytes, unknown/missing fields, duplicate/reordered members, unsupported class/mode/limit, and control-file membership. Each real builder constructs these exact policy bytes and the matching `FinalizationIdentity` in memory, then commits both as the two mode-`0444` members of the caller-selected absent evidence-directory transaction described in Task 8. Recovery accepts only a complete canonical evidence directory or an explicit content-free recovery report plus its reviewed SHA-256; it never treats one loose policy file as final evidence.

`build_canonical_zip()`, both independent verifier entry points, and `extract_verified_zip()` each receive the caller's independently reviewed `expected_source_binding_sha256`, compare it to the payload/manifest/archive record, and reject a self-consistent archive for another source or instance even when its artifact class and allowed-member policy are identical. The builder is pure: it creates bounded immutable bytes and a `ConstructedArchive`, never a path. `verify_canonical_zip_bytes()` requires explicit expected archive and manifest SHA-256 values, recomputes both, and independently parses exactly the supplied immutable bytes without reusing builder record objects. `verify_canonical_zip()` is the on-disk adapter: it opens the source once without following links, rejects a file larger than `maximum_archive_bytes` before allocation, reads at most 83,886,080 bytes, and delegates those exact bytes plus both expected digests to the byte verifier. Only either verifier can construct `VerifiedArchive`; the constructed type cannot satisfy extraction or finalization. `VerifiedArchive.archive_bytes` uses `field(repr=False)` and is excluded from receipts/logging. `extract_verified_zip()` recomputes its archive SHA-256, reparses its stored bytes independently under the explicit expected policy/source binding, and never opens or refers to an original archive path. This removes the construction-to-verification path-swap boundary and closes the later verification-to-extraction path-swap boundary with a fixed 80 MiB archive-input byte ceiling; it does not claim an 80 MiB process-RSS ceiling.

`canonical_source_identity_bytes()` emits canonical JSON with exactly `schema_version="macos-runner-guard.source-identity.v1"`, `expected_commit`, `expected_tree`, `observed_commit`, and `observed_tree`, using sorted keys, compact separators, ASCII UTF-8, and one final LF. It first requires all four object IDs to use the repository's one selected object format (40 or 64 lowercase hexadecimal characters), requires expected and observed commit/tree pairs to be equal after the separately verified Git relationship checks, and rejects unknown fields or mixed formats. `source_identity_sha256()` hashes only those canonical bytes. Tests pin the complete bytes/digest and reject field omission/addition, alternate ordering/whitespace presented as input, mixed object formats, uppercase/abbreviated IDs, and unequal expected/observed identities.

Every local header uses version-needed `10`, flags `0`, method `0`, DOS time `0`, DOS date `0x0021`, exact CRC-32 and sizes, and zero extra bytes. Every central header uses UNIX version-made-by `(3 << 8) | 30`, version-needed `10`, the same flags/method/time/date/CRC/sizes/name, zero extra/comment/disk/internal attributes, and external attributes `(stat.S_IFREG | mode) << 16`. The end record uses disk `0`, identical entry counts, exact central size/offset, and zero comment bytes.
